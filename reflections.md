# Reflections

I have been writing specific implementation prompts, then asking CodeBuddy which assumptions it is likely to make. I respond to those assumptions and uncertainties before combining the answers back into the implementation prompt. This helps reduce ambiguity and makes the final output much closer to what I actually want.

I also explicitly use parallelised, specialised subagents. This is useful because separate agents can investigate different parts of a task at the same time, each with a clear focus. It speeds up larger tasks and tends to produce more thorough results without losing structure.

Apart from that, before starting the implementation, I would set some conventions for the agents to follow across the repository to ensure consistency.
