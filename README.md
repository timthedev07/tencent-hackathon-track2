# Tencent Hackathon — Internal Enterprise AI Assistant

Permission-safe cross-platform enterprise AI assistant spanning Confluence, Jira, Slack, and Google Drive.

## Core Promise

**Permission-safe cross-platform retrieval.** Security takes precedence over recall or latency. Restricted source content must never reach the LLM, reranker, logs, or browser.

## Quick Start

Use an LTS Node.js release supported by the frontend toolchain: Node 22.22.2+
within the Node 22 line, Node 24.15.0+, or Node 26+.

```bash
# 1. Install dependencies
make install
make frontend-install

# 2. Copy env and start infrastructure
cp .env.example .env
docker compose up -d postgres redis minio

# 3. Run database migrations
make migrate

# 4. Seed synthetic fixtures (optional, for demo)
make seed

# 5. Start the API and worker
make dev          # API on :8000
make frontend-dev # Web on :3000

# 6. Run Celery worker (separate terminal)
uv run celery -A worker.celery_app worker --loglevel=info
```

### Use real provider data

The default `SOURCE_DATA_MODE=fixture` is intentionally a demo mode. The settings page labels its
synthetic records as **Demo data**; they are not files fetched from your provider accounts.

To use live data:

1. Set `SOURCE_DATA_MODE=live` in `.env` and provide the client ID, client secret and callback URL
   for each provider you want to use (`ATLASSIAN_*`, `SLACK_*`, or `GOOGLE_*`). Register the exact
   callback URLs shown in `.env.example` with those providers.
2. Restart the API and worker so they read the new environment. With Docker, run
   `docker compose up -d --build api worker web`.
3. Sign in, open **Connected sources**, select **Connect**, and complete the provider's OAuth consent
   flow. A client ID and secret alone do not grant access to a user's files.
4. Select the source's sync action. Atlassian exposes separate **Sync Confluence** and **Sync Jira**
   actions because they are indexed independently. Keep the worker running while each initial
   backfill is queued and processed.

Set a valid `MODEL_API_KEY` if you want answers generated by the configured remote model. In
development, an empty key selects the deterministic local gateway; a non-empty invalid key causes
remote requests to fail. Outside development, `MODEL_API_KEY` is required.

## Architecture

- **Browser**: Next.js (App Router) — sign-in, query UI, SSE progress, citations, audit viewer
- **API**: FastAPI — auth, query orchestrator, candidate retrieval, live authorisation, model gateway, output verifier, audit
- **Worker**: Celery — webhook ingestion, initial scans, reconciliation, normalisation, chunking, embeddings, deletion handling, audit checkpoints
- **Database**: PostgreSQL + pgvector (authoritative state, RLS, hybrid search, audit chain)
- **Queue**: Redis (Celery broker + ephemeral state only — never authoritative)
- **Object Store**: S3-compatible (signed audit-chain checkpoints)
